## Agent Studio

The Agent Studio is where you configure, test, and deploy agents.

![Agent Studio](/docs/images/agents/agent-studio.png)

### Accessing Agent Studio

1. Navigate to **Agents** from the sidebar
2. Click on any agent to open the Agent Studio
3. Or click **Create Agent** to build a new one

### Configuration Options

| Setting | Description |
|---------|-------------|
| **Name** | Agent display name |
| **Model** | AI model to use (GPT-4o, Claude 3.5 Sonnet, etc.) |
| **Description** | Brief description of the agent's purpose |
| **Temperature** | Controls response creativity (0 = deterministic, 1 = creative) |
| **Max Tokens** | Maximum response length |
| **System Prompt** | Instructions that define agent behavior |
| **Skills** | Capabilities the agent can use |
| **Connectors** | External systems the agent can access |

### Tabs

| Tab | Purpose |
|-----|---------|
| **Overview** | Configure agent settings and system prompt |
| **Tests** | Manage test cases and run evaluations |
| **Versions** | View version history and rollback changes |

### Actions

| Button | Action |
|--------|--------|
| **Evaluate** | Run test suite against the agent |
| **Save Draft** | Save changes without deploying |
| **Deploy** | Make changes live |

### System Prompt Best Practices

<Callout type="info">
System prompts define agent behavior and decision-making criteria. A well-crafted system prompt is critical for agent performance.
</Callout>

**Structure your system prompt with:**

1. **Role definition** - Who is the agent?
2. **Goals** - What should it accomplish?
3. **Decision criteria** - How should it decide?
4. **Constraints** - What should it ALWAYS/NEVER do?
5. **Tone and style** - How should it communicate?

**Example:**
```text
You are a compliance officer specializing in AML transaction monitoring.

Your role is to identify suspicious patterns and flag for SAR filing when needed.

Flag transactions if:
- Single transaction > $10,000
- Structured deposits (multiple <$10K to avoid reporting)
- High-risk jurisdictions (per FATF list)

ALWAYS:
- Cite regulatory sources (BSA, PATRIOT Act)
- Generate audit trail entries
- Escalate to human review when uncertain

NEVER:
- Make final SAR filing decision (requires human review)
- Ignore partial matches on watchlists
```

## Extended Thinking

<Callout type="warn">
For high-stakes decisions, extended thinking captures the agent's complete reasoning process for transparency and compliance.
</Callout>

**When to Use Extended Thinking:**
- Loan approvals/denials
- SAR (Suspicious Activity Report) decisions
- Large transaction approvals
- Customer risk classifications
- Trading decisions (market abuse detection)

**What Gets Captured:**
- Observation: What data was considered
- Analysis: How data was interpreted
- Decision: What conclusion was reached
- Factors: Which regulations were evaluated

**Performance Impact**:
- +10-20% tokens (higher cost)
- +0.5-1.5 seconds latency
- Worth it for high-stakes decisions

## Human-in-the-Loop Integration

Route high-risk decisions to human reviewers.

**Automatic HITL Triggers**:
- Risk score above threshold (configurable, default: 7/10)
- Dollar amount exceeds limit (e.g., >$250K)
- Missing decision factors detected
- Compliance flags present
- Manual escalation requested

**HITL Workflow**:
<Steps>
  <Step>
    Agent makes decision with reasoning
  </Step>
  <Step>
    Routing logic checks if HITL required
  </Step>
  <Step>
    Queue for review with compliance officer
  </Step>
  <Step>
    Human reviews full context, agent reasoning, all data
  </Step>
  <Step>
    Human decision: Approve, Deny, or Override
  </Step>
  <Step>
    Workflow resumes with human-approved decision
  </Step>
  <Step>
    Complete audit trail including human review
  </Step>
</Steps>

## Best Practices

<Accordions>
  <Accordion title="For Compliance Officers">
    1. **Always Enable Extended Thinking** for high-stakes decisions
    2. **Review HITL Queue Daily** to prevent backlog
    3. **Calibrate Risk Thresholds** based on your risk appetite
    4. **Monitor False Positives** and adjust agent prompts
    5. **Export Audit Trails Quarterly** for examination readiness
  </Accordion>
  <Accordion title="For Analysts">
    1. **Be Specific with Requests** (tickers, time periods, metrics)
    2. **Request Visualizations** when helpful for presentations
    3. **Verify Agent Calculations** for high-stakes analysis
    4. **Save Useful Prompts** as custom agents
    5. **Provide Feedback** on accuracy to improve agents
  </Accordion>
  <Accordion title="For Developers">
    1. **Start with Production Agents** before building custom
    2. **Test Custom Agents Thoroughly** before deployment
    3. **Use Minimal Skill Sets** to reduce cost
    4. **Monitor Token Usage** and optimize prompts
    5. **Version Control System Prompts** like code
  </Accordion>
  <Accordion title="For Administrators">
    1. **Monitor Cost by Agent** to identify optimization opportunities
    2. **Track Automation Rates** to measure ROI
    3. **Review Audit Logs Regularly** for compliance
    4. **Calibrate HITL Thresholds** based on queue depth
    5. **Update Models Periodically** as providers improve
  </Accordion>
</Accordions>
