Connectors let your AI agents communicate with external tools and services. Think of them as bridges that allow Oniva to talk to other software you already use in your organization.

## What Are Connectors?

In the real world, your financial operations likely involve multiple tools:
- **ServiceNow** for incident management
- **Slack** for team communication
- **Salesforce** for customer relationships
- **Jira** for project tracking
- **GitHub** for code repositories

Without connectors, your AI agents would be isolated - they could think and analyze, but couldn't take action in these systems. Connectors give your agents the ability to:

- **Read data** from external systems (get customer records, fetch tickets)
- **Create items** in external systems (open tickets, send messages)
- **Update records** (modify CRM entries, close incidents)
- **Automate workflows** across multiple tools

## Setting Up a Connector

<Steps>
  <Step>
    **Navigate to Connectors**

    Click **Settings** in the left sidebar (gear icon), then click **Connectors**. You'll see all available connectors.
  </Step>
  <Step>
    **Click Connect**

    Find the connector you want to set up and click the **Connect** button on the card. A configuration dialog will appear.
  </Step>
  <Step>
    **Enter Credentials**

    Fill in the required fields for your connector. Use API keys or OAuth credentials from your external service. Test the connection if available.
  </Step>
  <Step>
    **Save Configuration**

    Click **Save** to store your configuration. Credentials are encrypted before storage. The connector status will change to "Connected".
  </Step>
</Steps>

## Using Connectors in Workflows

Once configured, connectors become available in your workflows through the **Connector** node.

### Adding a Connector Node

1. Open the workflow editor
2. Drag a **Connector** node from the sidebar
3. Click on the node to configure it
4. Select which connector to use
5. Choose the action to perform
6. Map input data to the action parameters

### Example: Creating a Slack Alert

```
Start Node
    |
    v
LLM Node (Analyze data)
    |
    v
IF Node (Check if alert needed)
    | (Yes)
    v
Connector Node (Slack: Send Message)
    |
    v
End Node
```

## Security Best Practices

<Accordions>
  <Accordion title="Credential Management">
    - **Never share** connector credentials
    - **Rotate tokens** regularly (every 90 days recommended)
    - **Use service accounts** instead of personal accounts
    - **Limit permissions** to only what's needed
  </Accordion>
  <Accordion title="Access Control">
    - Only administrators should configure connectors
    - Review connector usage in audit logs
    - Disable unused connectors
    - Monitor for unusual activity
  </Accordion>
  <Accordion title="Data Protection">
    - Connectors encrypt credentials at rest
    - Connections use HTTPS/TLS
    - Sensitive data is masked in logs
    - API responses are not stored permanently
  </Accordion>
</Accordions>

## Troubleshooting

<Accordions>
  <Accordion title="Connection Failed Error">
    **Possible causes**:
    1. Invalid credentials
    2. Expired API token
    3. Network connectivity issues
    4. Service is down

    **Solutions**:
    1. Verify credentials are correct
    2. Generate new API token
    3. Check firewall settings
    4. Check external service status page
  </Accordion>
  <Accordion title="Unauthorized Error">
    **Possible causes**:
    1. Insufficient permissions
    2. Token doesn't have required scopes
    3. Account is disabled

    **Solutions**:
    1. Check account permissions in external service
    2. Regenerate token with proper scopes
    3. Contact your administrator
  </Accordion>
  <Accordion title="Rate Limited Error">
    **Possible causes**:
    1. Too many requests in short time
    2. API quota exceeded

    **Solutions**:
    1. Reduce workflow execution frequency
    2. Add delays between connector calls
    3. Upgrade API tier if needed
  </Accordion>
</Accordions>
