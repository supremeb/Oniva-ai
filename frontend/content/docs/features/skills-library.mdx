Skills are the building blocks of agent capabilities. Think of them as individual tools that agents can use to accomplish specific tasks - like web searching, running code, or reading files.

## What is a Skill?

A **skill** is a focused, reusable capability that an agent or workflow can invoke. Each skill:

- Does **one thing well** (single responsibility)
- Has defined **inputs and outputs**
- Can be **used by any agent** or in any workflow
- Has **version control** for stability

<Callout type="info">
**Think of it like**: If agents are employees, skills are the tools on their desk - a calculator, a phone, a web browser. Each tool does a specific job.
</Callout>

## Creating Custom Skills

You can create custom skills for your organization's specific needs.

### When to Create a Custom Skill

- You have a unique internal API to integrate
- You need specialized calculations
- You have domain-specific logic to encapsulate
- You want to standardize a common operation

### Custom Skill Structure

```python
# Example: Custom skill for internal credit score lookup
{
    "name": "lookup_internal_credit_score",
    "description": "Retrieves credit score from internal scoring system",
    "version": "1.0.0",
    "category": "compliance",
    "inputs": {
        "customer_id": {
            "type": "string",
            "required": True,
            "description": "Internal customer ID"
        }
    },
    "outputs": {
        "score": {
            "type": "number",
            "description": "Credit score (300-850)"
        },
        "factors": {
            "type": "array",
            "description": "Key factors affecting score"
        }
    }
}
```

### Skill Best Practices

<Steps>
  <Step>
    **Single Responsibility**: Each skill should do one thing well
  </Step>
  <Step>
    **Clear Naming**: Name skills clearly (verb_noun format)
  </Step>
  <Step>
    **Good Descriptions**: Write descriptions that help the AI use the skill correctly
  </Step>
  <Step>
    **Input Validation**: Define required inputs and types
  </Step>
  <Step>
    **Version Control**: Use semantic versioning (1.0.0)
  </Step>
  <Step>
    **Error Handling**: Return clear error messages
  </Step>
  <Step>
    **Documentation**: Include examples and edge cases
  </Step>
</Steps>

## Skills in Workflows

You can use skills directly in workflows without involving an agent.

### Skill Node

Add a **Skill Node** to your workflow to run a specific skill:

1. Drag "Skill" from the node palette
2. Select which skill to run
3. Connect inputs from previous nodes
4. Connect output to next node

This is faster and cheaper than using a full agent when you just need a specific capability.

## Skill Permissions

Control who can use which skills:

| Permission Level | Description |
|-----------------|-------------|
| **System** | Built-in skills, available to all agents |
| **Organization** | Custom skills your team created |
| **User** | Skills you created personally |

Administrators can restrict access to sensitive skills (like those that access external systems).
